# انتشار حساب‌روز روی همروش

این راهنما برای **آماده‌سازی و استقرار اولیه** است. داشتن این فایل به معنی انتشار واقعی، فعال بودن SSL، یا دریافت رخداد در Sentry نیست. انتخاب پلن و ساخت سرویس در حساب همروش ممکن است هزینه داشته باشد.

## ۱. شاخه و ساخت

مخزن: https://github.com/mdorgoli/architecture-research

شاخه: `feat/expense-manager-production`.
در دارکوب اپ از «منبع گیت» بسازید، همین مخزن و شاخه را انتخاب کنید. **build context ریشهٔ مخزن (`.`)، Dockerfile برابر `Dockerfile` و پورت سرویس `8000` است.** Dockerfile خودش پوشهٔ `expense-manager` را به `/app` کپی می‌کند. ساخت محلی معادل:

```sh
docker build -t expense-manager:local .
```

فایل‌های تحقیق در ایمیج قرار نمی‌گیرند. برنامه با کاربر غیر root اجرا می‌شود. نیازی به Redis یا Celery برای این امکانات نیست.

## ۲. PostgreSQL و متغیرهای محیطی

PostgreSQL را در شبکهٔ خصوصی قابل‌دسترسی از اپ بسازید. برای production کاربر دیتابیس اختصاصی با حداقل دسترسی لازم ایجاد کنید، نه superuser یا کاربر یک برنامهٔ دیگر. در پنل اپ مقادیر نمونهٔ `expense-manager/.env.production.example` را تنظیم کنید:

| متغیر | مقدار |
|---|---|
| `APP_ENV` | `production` |
| `DJANGO_SECRET_KEY` | کلید تصادفی حداقل ۵۰ نویسه؛ مقدار خصوصی |
| `DJANGO_ALLOWED_HOSTS` | دامنهٔ واقعی بدون scheme، به‌همراه `localhost,127.0.0.1` برای health check |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | آدرس کامل HTTPS همان دامنه؛ چند مقدار با کاما |
| `DATABASE_HOST`, `DATABASE_PORT` | host خصوصی دیتابیس و پورت، معمولاً ۵۴۳۲ |
| `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD` | اطلاعات دیتابیس اختصاصی |
| `DATABASE_SSLMODE` | پیش‌فرض `require`؛ TLS سرور دیتابیس را تأیید کنید |
| `SENTRY_DSN` | DSN پروژهٔ Django در Sentry؛ خصوصی وارد شود |
| `APP_RELEASE` | شناسهٔ نسخه یا commit منتشرشده |
| `PORT` | `8000` |
| `WEB_CONCURRENCY` | ابتدا `2`؛ با توجه به RAM و بار تنظیم شود |

اگر سرویس دیتابیس انتخابی فقط شبکهٔ خصوصی بدون TLS دارد، تغییر `DATABASE_SSLMODE=disable` یک تصمیم امنیتی صریح است، نه رفع خطای خودکار. دیتابیس نباید از اینترنت قابل‌دسترسی شود. `require` اتصال را رمز می‌کند ولی هویت سرور را مثل `verify-full` اعتبارسنجی نمی‌کند؛ در صورت ارائهٔ CA و hostname معتبر، `verify-full` همراه با CA معتبر libpq را استفاده کنید.

## ۳. اولین اجرا و migration

برای **اولین نصب با فقط یک replica**، فرمان اجرای اپ را `/app/entrypoint.sh bootstrap` قرار دهید. این مسیر ابتدا منتظر دیتابیس می‌ماند، سپس migration و collectstatic را اجرا می‌کند و Gunicorn را آغاز می‌کند. پس از آماده شدن اولیه، فرمان را `/app/entrypoint.sh web` کنید. دستور پیش‌فرض خود ایمیج نیز همین مسیر web است.

در نسخه‌های بعدی، قبل از بالا آمدن replicaهای جدید، در یک اجرای مجزای کنترل‌شده با همان ایمیج و متغیرها فرمان `/app/entrypoint.sh release` را یک بار اجرا کنید. اجرای web در صورت migration اعمال‌نشده متوقف می‌شود. migration هم‌زمان روی چند replica اجرا نکنید؛ قبل از تغییر schema از دیتابیس بکاپ بگیرید.

برای مدیر از کنسول خصوصی اپ `python manage.py createsuperuser` را اجرا کنید؛ رمز پیش‌فرض نداریم. برای آزمایش عادی از فرم ثبت‌نام استفاده کنید.

## ۴. دامنه، SSL و پراکسی

از بخش دامنهٔ اپ یک آدرس `darkube.app` یا دامنهٔ خودتان اختصاص دهید. برای دامنهٔ شخصی رکورد DNS را طبق مقدار نمایش‌داده‌شده در پنل تنظیم و گواهی معتبر SSL را فعال کنید. مقادیر host و CSRF را با دامنهٔ واقعی به‌روزرسانی کنید.

TLS در ingress خاتمه می‌یابد و Gunicorn روی پورت خصوصی HTTP گوش می‌دهد. **فقط بعد از تأیید اینکه ingress هدر `X-Forwarded-Proto` ورودی کاربر را حذف و مقدار صحیح را جای‌گذاری می‌کند**، `TRUST_PROXY_SSL_HEADER=1` بگذارید. پورت Gunicorn باید فقط پشت همان ingress در دسترس باشد. بدون این تأیید، اعتماد به هدر می‌تواند HTTPS را قابل دورزدن کند؛ با مقدار نادرست نیز حلقهٔ redirect رخ می‌دهد.

برنامه secure cookie، redirect به HTTPS، منع iframe، nosniff و HSTS یک‌ساله دارد. HSTS شامل زیردامنه‌ها و علامت preload است؛ بنابراین دامنه‌ای انتخاب کنید که همهٔ زیردامنه‌هایش فقط HTTPS باشند. این تنظیم به‌تنهایی دامنه را در فهرست preload مرورگر ثبت نمی‌کند. دو مسیر سلامت فقط وضعیت عمومی را برمی‌گردانند و از redirect معاف‌اند.

بررسی پس از استقرار:

```sh
python manage.py check --deploy --fail-level WARNING
python manage.py migrate --check
curl -I http://YOUR_REAL_DOMAIN/accounts/login/
curl -I https://YOUR_REAL_DOMAIN/accounts/login/
curl --fail https://YOUR_REAL_DOMAIN/health/ready/
```

HTTP باید به HTTPS هدایت شود؛ HTTPS بدون `-k` گواهی معتبر داشته باشد. صفحهٔ ورود و CSS باید ۲۰۰ بدهند. ثبت‌نام، ورود، ثبت هزینه، ویرایش، فیلتر، حذف و خروج را در دامنهٔ واقعی بررسی کنید. با کاربر دوم بررسی کنید اطلاعات کاربر اول قابل مشاهده/ویرایش/حذف نیست.

## ۵. مانیتورینگ

- liveness: `/health/live/`؛ readiness: `/health/ready/`، بررسی اتصال DB و کد ۵۰۳ در خرابی.
- در پنل، probeها را روی پورت ۸۰۰۰ تنظیم کنید؛ Host باید از فهرست مجاز باشد. healthcheck خود Docker جایگزین تنظیم probe در هر پلتفرم نیست.
- خطاهای اپ به stderr می‌روند؛ access log فقط status و زمان پاسخ را ثبت می‌کند.
- در Sentry، DSN پروژه را از پنل بگیرید و به متغیر محیطی اپ بدهید. خطاهای Django با SDK متصل می‌شوند؛ ارسال اطلاعات شخصی و performance tracing خاموش است.
- پس از تنظیم DSN، `python manage.py sentry_smoke` را از کنسول خصوصی اجرا کنید. **شناسهٔ چاپ‌شده اثبات تحویل نیست**؛ رخداد، environment و release را در داشبورد Sentry ببینید و alert آزمایشی را بررسی کنید. مسیر عمومی برای ایجاد عمدی خطا وجود ندارد.
- هشدار برای خطای جدید Sentry، تکرار خطا، readiness ناموفق و مصرف CPU/RAM در پنل زیرساخت تنظیم کنید.
- Axes براساس IP سوکت و نام کاربری محدودسازی می‌کند. پشت پراکسی مشترک، تنظیم استخراج IP واقعی مورداعتماد یا محدودسازی لبه‌ای لازم است؛ به `X-Forwarded-For` دلخواه کاربران اعتماد نکنید. نرخ ثبت‌نام عمومی را در لبه محدود کنید.

## ۶. بکاپ و بازگشت نسخه

بکاپ دوره‌ای PostgreSQL را در سرویس دیتابیس فعال کنید و قبل از تحویل، بازیابی یک بکاپ را در دیتابیس آزمایشی مجزا امتحان کنید. زمان نگهداری بکاپ و گزارش‌ها را تعیین کنید. هرگز بازیابی آزمایشی را روی دیتابیس اصلی انجام ندهید.
نسخهٔ قبلی ایمیج را نگه دارید. rollback کد فقط در صورت سازگاری schema مجاز است؛ migration را بدون بررسی معکوس نکنید. برنامه فایل آپلودشده ندارد و دادهٔ ماندگار فقط در PostgreSQL است.

## ۷. تحویل تمرین

بعد از push موفق شاخه و بررسی واقعی استقرار، `expense-submission.txt` در ریشهٔ مخزن را با URL واقعی HTTPS و نتیجهٔ Sentry تکمیل کنید. فایل فعلی باید صادقانه وضعیت منتشرنشده را نشان دهد؛ URL فرضی برای نسخهٔ آنلاین نسازید.
